# git分支
在 Git 中新建分支主要有以下几种常见方式，可以根据实际需求选择：

## 创建并切换到新分支（最常用）
如果你希望新建一个分支并立即在该分支上工作，可以使用 -b 参数，一步到位：

```bash
git checkout -b <新分支名>
```
例：
```bash
git checkout -b master2
```
注：如果你的 Git 版本是 2.23 或更高，也可以使用新语法 git switch -c <新分支名>。
## 切换分支
```bash
git checkout <分支名>
```

## 仅创建分支（不切换）
如果你只想新建分支，但希望继续留在当前分支，可以使用：

```bash
git branch <新分支名>
```
创建后，你可以随时使用 git checkout <新分支名> 手动切换过去。
## 查看分支
默认查看本地分支
```bash
git branch
```

```bash
git branch -a          # 查看所有分支（本地+远程跟踪）
git branch -r          # 只查看远程跟踪分支
```
## 删除分支
**安全删除**（分支已合并到当前分支或其他分支）：
  ```bash
  git branch -d 分支名
  ```
- **强制删除**（分支未合并，但确认不需要）：
  ```bash
  git branch -D 分支名
  ```

⚠️ **注意**：不能删除当前所在的分支。请先切换到其他分支：
```bash
git checkout main   # 或 git switch main
git branch -d 分支名
```
## 基于特定分支或提交创建
默认情况下，新分支会基于你当前所在的分支创建。如果你想基于其他分支或某个特定的提交记录来创建，可以在命令后加上源分支名或提交 ID：
```bash
git checkout -b <新分支名> <源分支名或提交ID>
```

💡 最佳实践建议
- 命名规范：建议使用有明确含义的前缀来命名，例如功能分支用 feature/xxx，修复分支用 `bugfix/xxx` 或 `hotfix/xxx`，避免使用 `tmp` 等模糊名称。
- 查看分支：创建后，可以使用 git branch 命令查看本地所有分支，当前所在分支前会带有一个 * 标记。
- 推送到远程：新建的分支默认只在本地，如果需要推送到 GitHub 等远程仓库，可以执行 git push -u origin <新分支名>。

# 上传github
## 初始化本地git仓库

打开终端（或 Git Bash），进入你想要上传的文件夹目录，并执行以下命令来初始化一个新的 Git 仓库：

```bash
cd path_to_your_folder
git init
```

注：如果你使用的是 Git 2.28.0 或更高版本，可以使用 git init -b main 来直接将默认分支设置为 main。

## 添加文件到暂存区
将文件夹中的所有文件和子文件夹添加到 Git 的暂存区。使用以下命令：
```bash
git add .
```

注：这里的 . 代表当前目录下的所有文件。如果只想上传特定的文件夹，可以将 . 替换为该文件夹的相对路径，例如 `git add folder/`。有多个文件用空格分开，例如：`git add folder1/ folder2/`

## 提交更改到本地仓库
将暂存区的文件提交到本地仓库，并添加一条提交信息：
```bash
git commit -m "Initial commit"
```
- 注：“Initial commit” 是提交信息，你可以根据实际情况修改为其他有意义的描述。

## 创建远程仓库并关联
首先，在 GitHub 网页上创建一个新的空仓库，并复制该仓库的 URL 地址。然后在本地终端中运行以下命令，将本地仓库与远程仓库关联：
```bash
git remote add origin <你的GitHub仓库URL>
```
注：请将 <你的GitHub仓库URL> 替换为真实的 GitHub 仓库地址。

## 推送到 GitHub
最后，将本地仓库的内容推送到 GitHub 远程仓库：
```bash
git push -u origin main
```
注：如果你的默认分支是 master，请将命令中的 main 替换为 master。首次推送时，-u 参数会将本地分支与远程分支建立追踪关系，后续推送可直接使用 git push。

⚠️ 重要注意事项：
- 敏感信息： 切勿将敏感信息（如密码、API 密钥或令牌）通过 git add、commit 或 push 到远程仓库。如果已经添加，请务必从文件中删除并清理历史记录。
- 文件大小限制： 通过浏览器上传单个文件的大小限制为 `25 MiB`，而通过命令行最大可达 100 MiB。如果文件夹中包含大于 100 MiB 的文件，需要使用 Git Large File Storage (LFS)。
- 远程仓库状态： 推送前，请确保你在 GitHub 上创建的是一个空仓库。如果远程仓库不为空（例如创建时勾选了初始化 `README` 文件），直接推送可能会失败。此时你可能需要先执行 git pull origin main --allow-unrelated-histories 拉取远程内容，解决冲突后再推送。

# git本地版本控制
## 初始化本地git仓库

打开终端（或 Git Bash），进入你想要上传的文件夹目录，并执行以下命令来初始化一个新的 Git 仓库：

```bash
cd path_to_your_folder
git init
```

注：如果你使用的是 Git 2.28.0 或更高版本，可以使用 git init -b main 来直接将默认分支设置为 main。
## 添加所有文件并提交
```bash
git add .   # 将代码进行暂存
git commit -m "当前版本代码，保存一下，保存说明"   # 提交版本
```
## 常用的回滚命令：git reset

在 Git 中，我们通常用 HEAD 来代表“当前所在的最新版本”。要回退到之前的版本，我们只需要告诉 Git 往回退几步：
- HEAD~1：代表上一次提交（往回退 1 步）
- HEAD~2：代表上上次提交（往回退 2 步）
- HEAD~3：代表上上上次提交（往回退 3 步）

假设你想回滚到“上一次”提交，你可以使用 git reset 命令。但这里有一个非常重要的细节：Git 提供了三种不同的“回滚力度”，取决于你想怎么处理回滚后的代码。

### 1. 最温和的回滚（保留代码，仅撤销提交记录）
```bash
git reset --soft HEAD~1
```

效果：提交记录被撤销了，但你刚刚写的代码完好无损地留在暂存区。
适用场景：你只是觉得刚才写的“提交说明（commit message）”没写好，想重新提交一次。

### 2. 常规的回滚（保留代码，但取消暂存）
```bash
git reset HEAD~1  # 默认就是 --mixed 模式
```
效果：提交记录被撤销了，代码也还在，但被退回到了“工作区”（也就是你刚写完代码，还没执行 git add 的状态）。
适用场景：你发现刚才提交的代码有 bug，想重新修改一下再提交。这是日常开发中最常用的方式。

### 3. 最狠的回滚（彻底丢弃代码和记录）
```bash
git reset --hard HEAD~1
```

效果：提交记录被撤销，你刚才写的代码也被彻底删除了，电脑里的文件直接变回上一次提交时的样子。
适用场景：你确定刚才写的代码完全是一堆垃圾，一秒钟都不想保留，想彻底扔掉。

### 💡 保命秘籍：后悔药 `git reflog`

别怕，Git 给你留了一颗后悔药，叫做 `git reflog。`
它会记录你在本地仓库的所有操作轨迹。哪怕你用了最狠的 --hard 把代码弄丢了，只要你执行：
`git reflog`

你就能在屏幕上看到类似这样的记录：
`a1b2c3d HEAD@{0}: reset: moving to HEAD~1`
`f4e5d6c HEAD@{1}: commit`: 刚才被我删掉的那次提交
...

你只需要把 `f4e5d6c` 这个哈希值复制下来，执行：
`git reset --hard f4e5d6c`

你的代码就瞬间复活了！

总结建议：
既然你打算在本地慢慢写、随时回滚，记住这个万能公式就够了：
1. 想撤销提交但保留代码：git reset HEAD~1 （回退1次）或 git reset HEAD~2 （回退2次）。
2. 万一搞砸了：git reflog 找回代码。

你可以先随便写几行代码，提交一次，然后再试着回滚一次，亲自体验一下这个“时光倒流”的过程！
